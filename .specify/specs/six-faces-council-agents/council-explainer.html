How the Council Works

The six faces in practice: what happens when you call them, where everything lives, why your other chats can't see them yet, and what a Claude mod would add. Written 2026-10-02.

The short answer. The council is a skill: a set of written instructions plus one data file, faces.yaml, that Claude reads when you ask for the six. Until today the skill lived on unmerged branches, so no session could load it. It is now merged in friendcraft and flirtcraft, and bars-engine is merging. Even merged, a repo's skill reaches only Claude Code sessions opened on that repo. Ordinary chats, the desktop and mobile apps, and your other repos never read it. One upload to your claude.ai account fixes that, and the package is ready.

What the council is made of

No server runs and no agent sits waiting. The council is four pieces, and Claude reads them when you call it.

PieceWhat it holdsWhere
The skillHow to run a pass or a term pass: the shape, the order of faces, the reach test, where results land..claude/skills/six-faces/ in each of the three repos
The definition fileEach face's altitude, lens, term test, and lessons in your own words. Also the reserved list and your ruling that the Sage never decides.council/faces.yaml, kept identical across repos by a check
The boardEvery position, question and term waiting on you, with buttons. It is the one piece you touch.Council Board, on claude.ai, any device
The ledgerOne record per pass and per board read: the question, the faces, what you ruled. The stats script counts these.council/ledger/ and the spec folder in bars-engine

One pass, step by step

  1. You, in chat
    Ask in a Claude Code session on one of the three repos. Plain words work: get the six on this, let the faces weigh in, run a term pass. Chat is where you give context and steer.
  2. Claude
    Claude loads the skill, reads faces.yaml, and gathers evidence: files, logs, past rulings. Each face argues from its lens and carries its lessons. The Sage synthesises, lists the dissent, and decides nothing.
  3. Claude
    Before any question reaches you, Claude tries to answer it from the record. A question gets through only if the answer is your preference or a fact only you hold, and only if it changes what gets built.
  4. Claude
    The pass is written as a file beside what it is about. Positions and real questions go onto the board. The chat reply is what changed and a link.
  5. You, on the board
    Flip a position you disagree with, answer a question, rename or retire a term, or type a steer. Save each row. This works from your phone.
  6. Claude, next time you write
    Tell Claude you saved. Claude reads the board, writes a ledger record, and turns any overrule or steer into a lesson for that face, quoted exactly. Adopted terms go into the repo's glossary as proposed, with a decision-log entry. The next pass carries all of it.

Today's real case

You asked for flirtcraft's failing deploys as a test. Claude traced the cause in the build log. Vercel's installer blocks Prisma's setup script, so the database client never gets built and the type check fails. Claude reproduced the failure exactly, proved a one-line fix, and ran the tests. The six then argued what the fix ships: the live site is from August 31, and 50 commits wait behind the broken build. Five positions needed nothing from you. One question did, because only you can see the production settings: when to merge. It is on the board now, and the fix waits as pull request #2.

Making it reach everywhere

Now: upload the skill to your account

The package is attached in chat as six-faces-skill.zip. Upload it at claude.ai, under Settings, then Customize, then Skills. It holds a copy of the skill written for places with no repo, plus today's faces.yaml. Without a repo, a pass ends with a short record block that a repo session pastes into the ledger later.

The catch is that the upload is a snapshot. When a face gains a lesson, the uploaded copy does not change. Rebuild the zip with python3 council/package_skill.py and upload it again. The snapshot date sits inside the package, so a pass can say how old its lessons are.

Later: a connector, if the snapshot becomes a problem

A connector added at claude.ai, under Settings, then Customize, then Connectors, reaches chats, the desktop app and Claude Code, and it reads the live files. It needs a server on a public web address with sign-in. The first pass deferred it until a second person needs the council. It is also the fix if re-uploading feels like a chore.

What a Claude mod would add

A mod is a plugin that runs inside Claude Code itself. It can add commands, draw panels, watch what Claude does, and register agent types. For the council it could do six jobs.

  • A /six command that starts a pass, and /terms for a term pass.
  • Six real agents. Each face becomes its own agent type with its own prompt and its own model. Running the Challenger on a different model from the other five is the published fix for faces sharing one blind spot.
  • The board as a side panel beside the conversation, so you flip and answer without leaving.
  • A line above the prompt that says when questions are waiting for you, such as 2 questions on the board.
  • Lessons in every session. The faces' lessons would be added to Claude's instructions automatically, even when you never call the six.
  • A guard on the definition file that refuses edits to faces.yaml unless they come from your ruling.

The limit matters for how you work. A mod runs in Claude Code on your own computer: the terminal, the desktop app's Code tab, or an editor. Cloud sessions at claude.ai/code, where this conversation runs, do not load plugins from a computer or from a repo's settings. An organization admin can provision them for everyone. So a mod would help most if you start using Claude Code locally. For the web sessions you use now, the uploaded skill does the job.
