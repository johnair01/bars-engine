# Six faces, pass one — *how the council gets built*

**2026-10-02.** Called by Wendell on the proposal in `spec.md`, with one ruling already made and one
anchor supplied. The ruling: the faces speak as faces, not as the game's NPCs. The anchor, in his words:
*"The greatest utility is as part of my Claude decision making flow."*

**The proposal under review was written by the same author as this pass.** Read every face with that
in hand. A pass that agrees with its author has not argued.

---

## Anchor

The council exists to make Wendell's decisions better at the place he makes them, which is in
conversation with Claude. Every other door is secondary and has to earn its place.

---

## 🧠 Architect — structure

**The proposal answers the wrong question first.** It asks whether to build the command line or the
MCP tools first. Under the anchor, the question is what must be true in every Claude surface Wendell
decides in: a Claude Code session in any of five repos, Claude Desktop, the claude.ai app. The answer
is that the council has to be **readable where Claude already is**, and none of those surfaces has
bars-engine's Python backend, its Postgres or its OpenAI key.

**So the council is a prompt pack and a record schema, not a fourth implementation of the faces.** The
game has one in Python. The passes have one in markdown. The spec proposes a third in Python. A
definition file and a skill that reads it is a structure with no runtime of its own, and it runs
inside whatever runtime Wendell is already in.

**The ledger location reverses.** The spec recommended one ledger in bars-engine. A friendcraft session
cannot see bars-engine, so a record there is invisible at the moment it is needed. **The record lives
in the repo whose decision it is.** The definition file travels the way `house-voice` travelled from
`mtgoa-manuscript`: copied into each repo, with a lockstep check so copies cannot drift.

**The Python council agents move to the last phase**, built only when a surface that cannot read a
file needs them.

## 🏛 Regent — what to preserve

**Preserve the shape that works.** Scorecard, anchor, six lenses, verdicts table, dissent check, and a
landing that ends *for Wendell to rule*. Eleven passes in six weeks produced rulings in that shape.
The spec keeps it, and nothing in this pass changes it.

**Preserve the decision log as the one place a ruling lands.** The inventory found passes four and
six were never logged. The weak step is not the arguing, it is the recording of what Wendell said
afterwards. A second ledger that holds rulings would drift from `DECISION_LOG.md` the way the April
ontology drifted from MTGOA's July fix. **A ruling is written once, in the decision log. The record
points to it.** The skill writes both in the same step, so a pass cannot close unlogged.

**Preserve the rule that no number is inferred on Wendell's behalf.** The run length for ceding stays
unset until he sets it. The Regent adds one item to the reserved list: **the council may never change
its own definition file.** A face that can rewrite its lens on the strength of its own ruling is a
face with no altitude.

**Definition of done for the first phase:** a pass convened in a Claude session uses the skill, the
author improvises no lens, and the record and the decision-log entry exist when the pass closes.

## ⚔️ Challenger — what gets wrong

**The proposal builds an engine for a practice that works with no code.** Three phases, a Python
package, a command line, MCP tools, an HTTP route. Pass one of friendcraft's own series said the engine
is what made the last book late. The schema question is the safe work, as pass six said of itself: a
ledger cannot be wrong until something reads it.

**The learning signal is thinner than the spec admits.** Two overrules are on record across seventy-one
deliberations. Agreement is silent, so nobody wrote it down, so the ledger starts with nothing to learn
from. A loop that cedes on evidence needs the evidence recorded every time, including the boring
times, and the record shows that step skipped in two passes of six.

**The second-model idea for the Challenger is the author's, untested, and it is a tidy story.** It is cheap
to try, and it does not belong in a design-decisions table until it has been tried.

**The honest version of the build is a page.** A skill file, a definition file with a lessons list,
and the habit of writing the ruling. Run that ten times. Then decide whether anything needs code.

**No ledger fixes this:** Wendell convenes faces in conversation, in passing, more often than any
file records. The ledger counts passes that go through the skill. Say so, and do not read the count as
the practice.

## 🎭 Diplomat — what bridges

**The ruling that the faces speak as faces settles the bridge to the game.** The game's NPCs and the
council share a name and an altitude, and nothing else. `faces.yaml` holds name, altitude and lens.
The NPC lore stays in `_lore.py`. Neither reaches into the other.

**Who is excluded by a council that lives in Wendell's Claude account.** The one non-Wendell loop,
which pass six's scorecard says has never existed. A collaborator cannot open his session. The MCP
and command-line doors are for them, so *outside Claude Code* is not only a convenience for Wendell.
It is how a second person ever convenes the six. That keeps those doors in the plan, later, for a
stated reason.

**The precedent for copying a standard into each repo carries its own warning.** `house-voice` was
copied and stayed true. The April ontology was copied and dropped Open Up for three months. The
difference was a check. The lockstep script the Architect asks for is the Diplomat's condition too.

**On the words.** *Advisory*, *delegated* and *reserved* can be acted on without a follow-up question.
Keep them.

## 🌊 Shaman — felt sense

**What is moving underneath the ask is fatigue.** Four times in `CLAUDE.md` a session imported a premise
nobody gave it and argued the book against it. Wendell wants his judgment to compound, so the fifth
session does not repeat the first session's error. The council is wanted as a guard against the
session's blind sector at least as much as a deliberator.

**The lessons list touches that wound and the rest of the proposal does not.** It carries Wendell's own words into
the next face's prompt. The command line does not touch it and the stats do not. If only one piece ships, it is that list.

**The felt risk is the one pass six proved.** Six faces written by one model in one session is the
blind sector wearing six masks. This pass is an instance. The dissent below is against the author's
plan, which is the right direction, and it is still one author.

**Delegation has one more risk.** The §2c test passes: the ceding table rates what a face has learned, not a person.
The risk is the other one. A Claude deciding alone because a table said it may, on a question that
resembles a prior one, is the manufactured-wisdom failure with a permission slip. **The tell will be
that the delegated answer reads smooth.** So a delegated face produces a draft ruling that Wendell
confirms with a word. It never produces a silent decision.

## 📖 Sage — panoramic

**The five do not agree on where to start, and that is the finding.** The Architect says the
definition file and the skill. The Regent says the recording step. The Challenger says no code at all.
The Diplomat says the doors for a second person. The Shaman says the lessons list. **They converge on
one point: the council is a skill and two data files inside the Claude flow, and code only where a
surface cannot read a file.**

**The order that honours all five:**

1. `faces.yaml` with the six lenses, sources cited, and a `lessons` list per face. Copied into each
   repo, with a lockstep check.
2. A `six-faces` skill that reads it, convenes the pass in this shape, ends in a landing, and writes
   the record and the decision-log entry in one step.
3. A stats script over the records, run from any repo that has them.
4. The MCP tool, wrapping the same prompts, for Claude Desktop and for a second person.
5. Ceding, after the records carry rulings, with the run length Wendell sets and delegation as a
   draft he confirms.

**The Python council agents and the HTTP route leave the plan** until step 4 shows a need.

## Where the pass lands, for Wendell to rule

**On the build:** a definition file with lessons, a skill that convenes and records, a stats script.
Nothing in Python until a surface needs it. The spec's phases 1 and 3 change to match.

**On the ledger:** one record per repo, beside the decision it belongs to, pointing at the decision-log
entry that holds the ruling.

**On ceding:** the run length stays his. A delegated face drafts; he confirms.

**On the reserved list:** add that the council never edits its own definition file.

**On the model:** the one he is talking to. The second-model experiment moves out of the design table
and into a note.

**On the six:** the council uses the altitude six, and the doctrine six become masks.
