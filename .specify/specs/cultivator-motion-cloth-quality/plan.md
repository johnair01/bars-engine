# Plan: cultivator motion and cloth quality

## Constitution check

| Article concern | How this plan answers it |
|---|---|
| Evidence before new work | Reuse the existing figure, garments, motion lab, cloud captures and user notes; record the absent round recipe. |
| User authority | Wendell judges the look at named frames. Numeric gates only reject technical defects. |
| Small, reversible steps | First expose the built body matrix, then measure contact, then compare cloth candidates on B2. |
| Provenance | Keep a versioned recipe, controls, phase, camera, notes and before/after captures. |
| Capacity | Run repeated build and capture in GitHub Actions; use the Mac for focused viewing and notes. |

## Sequence

1. **Expose variation.** Pass `build` and `height` into `makeWalker`, expose them in the motion lab, show actual stature, and save them with notes. Disable and name `round` until the real 3D recipe exists. Capture four boundary examples plus the two default bodies in CI.
2. **Establish baselines.** Run the full five-combination-per-base matrix at fixed run and jump phases. Measure contact, knee spacing, intersections and hem motion in metres and as fractions of stature. Preserve frames and metrics together.
3. **Fix body-relative motion.** Decide explicitly which offsets scale with stature: run compression and flight, jump height and travel, arm clearance, contact tolerance, cloth trail/flare. Re-check each boundary. Keep authored physical speed where world metres are intentional.
4. **Prototype B2 cloth.** Compare rigid skinning, the current phase-driven preview, and one constrained secondary-motion method with waist attachment, hem clearance and leg collision. Use the same captures and reject candidates that harm the approved walk.
5. **Review and teach.** Record Wendell's phase-specific keep/change notes, freeze a reference reel, turn the winning method into parameter bounds and a reproducible build manifest, then expand to other garments.

## Capacity limits

Use one B2 robe and the existing two body bases first. Cloud Chromium creates the contact sheets; no local Blender bake, new paid asset service, or full cloth solver is assumed. The first matrix is small enough to finish in one cloud run. Full cross-product and round build follow the first contact report.

## Falsification checkpoints

- If build/height controls do not change the actual rendered recipe, stop before cloth work.
- If world-unit motion offsets drift visibly across stature, normalize or declare the physical unit before tuning cloth.
- If the bounded cloth candidate creates more penetrations or rebound than rigid skinning on any boundary body, reject it.
- If Wendell still reads the result as rigid, jittery or weightless, retain that note as a failed visual gate even when metrics pass.
