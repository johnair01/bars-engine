# Six faces: *the Ontology Alchemy Game, its map and an interactive WAVE*

Wendell called this pass on 6 October 2026, in the project thread "Live, shareable ontology game".
**Pass:** first council pass on the site build of the game (pull request johnair01/bars-engine #260).

**The question, in his words.** "It's solid as a state engine but the output should be a map of where the
player has gone. I think that WAVE should be more interactive. The practice is designed that one is
supposed to breathe through all the steps. They should be troubleshooting as part of this process for
instance if something is blocking welcoming a feeling in the player should be able to work on that block
and it should route them back to where they started when the block emerged. This can happen for all the
steps in the A (acknowledge, allow, accept, appreciate) Each of those can be blocked and call in working
through that block as well On top of all of this this work should be going through the council board and
having the 6 game masters weighing in on design choices etc."

## Scorecard

No earlier pass on this game set tests. The artifact's own design notes (the V2 UI specs and the onboarding
audit of 26 September) predate the council and are read here as record, not graded.

## Anchor

The game finds where a charge sits in the five-element cycle and lets the body finish the turn. The site
build exists so Wendell can send a client a link to practise with. This pass adds the two pieces he asked for:
a map as the game's output, and a WAVE that is breathed step by step and can stop to work a block.

## Shaman (magenta)

**The Shaman hears the request as one about return.** A block on Welcome is the felt sense saying "not this
yet". Wendell's ruling of 9 September holds here: "We shouldn't assume a block, but if there IS a block we
should assume self-sabotage, with the given choice to skip if that's not a frame that works for the user."
So every step offers a way through and a way to name a block, and a named block opens with the
self-sabotage frame and a plain skip.

**The Shaman wants the breath to be the clock.** The practice is breathed, so each step lasts one guided
breath. The continue button appears when the exhale ends. That is an offer of pace, never a lock, because
an offer is not a requirement (lesson, 9 September).

**The Shaman wants the map to be something the player keeps.** Wendell's ruling of 3 October says the
player leaves with a move they can use. The map shows the route, and under it the belief the player last
held, in the player's own words. The belief stays on the device: it is drawn on screen and in the saved
image, and never written to storage, which keeps the Mode A boundary of 24 September.

**Risk.** A block opened inside a block can feel like falling. The way back must always be visible.

## Architect (orange)

**The Architect says the game already owns a block engine.** Phase 1 to Phase 5 is exactly "find a block,
name it, hold a true belief, see if it shifts". Working a WAVE block through the same cycle needs no second
machine. The new piece is a return stack: when a step is blocked, the game saves the step and everything
the cycle needs, runs the block work, and on completion restores the saved state and resumes at that step.

**The saved states form a stack, not a flag.** A block can arise inside block work, so the saved states form a stack of any depth.
Each frame records which WAVE step it came from. The map draws each frame as a loop off the stop where it
emerged.

**The map is drawn from data the game already keeps.** `resolvedThreads`, `deferredThreads`, the
history of Flow Forward, Tempering and Go Deeper, and dead ends already hold the route. The map needs one
ordered log of stops and moves, appended at the same handlers that update those lists, plus the WAVE
detours. It is an SVG on the five-node wheel the game already draws.

**The A is a ladder.** Wendell named four rungs today: Acknowledge, Allow, Accept, Appreciate. The current
build lets the player pick one of three. A ladder climbed one breath per rung lets each rung be blocked,
which is what he asked for, and lets a player stop at the rung they can honestly reach.

## Challenger (red)

**The Challenger tests the return, because the return is the whole request.** If a block on Accept, worked
through a cycle that itself hits a block on Welcome, does not land the player back on Accept with the same
charge, the feature failed. That is falsification test one.

**The Challenger names three ways this breaks.** First, block work could overwrite the outer cycle's
channel, face and belief, so the return lands on the right step with the wrong charge. Saving the whole
cycle state in the frame prevents it. Second, a player who blocks on every rung can loop without landing.
The game already answers over-naming with a reflection at three named threads; the same reflection at a
stack depth of three answers this, with the stop and pause exits in reach. Third, the 49-step guided demo
clicks real buttons by key; a reworked WAVE must not move the keys the demo uses.

**The Challenger sets a test against the map.** A map that cannot be read without a legend has failed. The
test: shown the map after the demo run, a reader names the first channel, the move that left it and the
channel where the cycle ended.

## Regent (amber)

**The Regent preserves these.** The safety container text, the stop, leave-for-today and pause exits on every
in-progress screen including block work, the no-belief-text storage rule, the coach code, and the guided
demo all stay as they are.

**The Regent names one obligation.** Mastering the Game of Allyship defines WAVE as Welcome, Acknowledge, Validate,
Exhale (`appendices/APPENDIX_C_KEY_TERMS.md`). Canonical prose is reserved to Wendell, so this pass does not
touch the book. The game uses the four-rung A from his message of today and says so in a code comment. Any
change to the book's definition is his to make in the manuscript.

**The work is done when** both falsification tests pass in a browser test, the existing 19 checks still pass,
the demo runs end to end, and the work rides pull request #260, which merges only on his word.

## Diplomat (green)

**Copy that does not shame.** The block button reads "Something's in the way". The self-sabotage frame reads
as an invitation with a skip beside it. The ladder's stop reads "This is as far as I can honestly go
today", and stopping there is a complete WAVE.

**The Diplomat builds a bridge for a client.** A client arrives from a link and has never heard of a channel or a face. The map
uses plain words on its labels (Anger, Fear, the face names the game already shows) and one sentence under
it that says what the lines mean.

**Both tracks hold.** All of this is scripted. No language model runs anywhere in the game.

## Dissent check

The pass was not unanimous. The Shaman would work a block by meeting the voice that is blocking, the way the
Big Mind interview meets a voice, because Wendell's ruling says to assume self-sabotage when there is a block.
The Architect, Challenger and Regent would run the block through the game's own cycle, because the cycle
already exists and the daemon ontology is still a proposal (Daemons from Big Mind, Findings and Proposal
v0, unruled). That split is the one question this pass sends to the board.

## Sage (teal)

**What the Sage keeps.** The Sage keeps the Shaman's breath as the clock, the self-sabotage frame with a
skip, and the belief kept on the map. It keeps the Architect's return stack and single route log, the
Challenger's return test, depth reflection and demo keys, the Regent's exits inside block work and the
untouched book, and the Diplomat's copy and plain map labels.

**What the Sage drops.** The Sage drops nothing in this pass.

**Order of work.** The route log and the map come first, since the map must show WAVE detours and those
detours need the log. The breathed ladder comes second. The return stack comes third, built on the
recommended option of the open question, and changed if Wendell chooses another.

## Outputs

### Positions (stand unless Wendell flips them)

1. **oag-map-output.** The game's output is a map of the player's route drawn on the five-element wheel: one
   numbered stop per channel visited, with its face and where it landed; solid arrows for Flow Forward,
   dashed for Tempering; a stub for a dead end; a hollow mark for a thread set aside; a ring for Go Deeper;
   a small loop for each WAVE block. It leads the Cycle Complete screen, with the last held belief beneath
   it and a button to save it as an image. *Why not asked:* Wendell named the output today; the drawing is
   built from state the game keeps.
2. **oag-map-private.** The map's belief text is drawn on screen and in the saved image only, never stored.
   *Why not asked:* the Mode A boundary of 24 September stores no belief text.
3. **oag-wave-breath.** Each WAVE step is one guided breath, and its continue button appears when the exhale
   ends. *Why not asked:* his message says the practice is breathed through all the steps; the Shaman
   lesson of 9 September makes pace an offer, so nothing else is locked. The breath length (four seconds in,
   six out) is the council's number and a placeholder.
4. **oag-wave-ladder.** The A is a ladder of Acknowledge, Allow, Accept, Appreciate, one breath per rung,
   climbed in order. The player may stop at any rung, and stopping is a complete WAVE. *Why not asked:* he
   named the four rungs and said each can be blocked.
5. **oag-wave-blocks.** Every step and every rung offers "Something's in the way". Choosing it opens the
   self-sabotage frame with a skip, then the block work, then returns the player to the exact step where the
   block emerged, with the outer charge unchanged. Blocks can nest; each nested block returns to its own
   step. *Why not asked:* his message describes this routing directly; the frame is his ruling of 9
   September.
6. **oag-wave-depth.** At three nested blocks the game names the pattern once, as it does for over-naming,
   and keeps stop and pause in reach. It does not cap the depth. *Why not asked:* the over-naming reflection
   of 23 September is the precedent; the number three is the council's.
7. **oag-book-untouched.** The book's WAVE stays Welcome, Acknowledge, Validate, Exhale until Wendell edits
   the manuscript. *Why not asked:* canonical prose is reserved to him.

### Questions (passed the reach test)

1. **oag-block-work** (owner: Architect, with the Shaman dissenting). *How should the game work a blocked WAVE
   step?*
   - **A. Through the game's own cycle (recommended).** The block is located in the body, given a channel and
     a face, and held with a true belief until it shifts, then the player returns to the step. Builds now on
     the existing engine.
   - **B. Through a smaller WAVE on the block itself.** The player welcomes and breathes with what is in the
     way, then returns. Quicker and gentler, and it never names a channel or a face.
   - **C. By meeting the voice that is blocking.** A short interview with the daemon in the way (its job, who it
     works for, whether it will step aside), then the return. Closest to Big Mind, and it waits on the daemon
     ontology you have not yet ruled.

   *Why only you:* it is a choice about what the practice is, and the record holds a preference for A's
   engine and a ruling (self-sabotage) that points toward C. *Why not asked before:* the blocked step did
   not exist until today's message. *Meanwhile:* the build proceeds on A, and B or C replaces only the block
   work, not the stack or the map.

## Falsification tests (set 6 October 2026)

1. **The return.** A browser test blocks on Accept, works the block, blocks again on Welcome inside it, works
   that, and lands back on Welcome inside the block work and then on Accept with the outer channel, face and
   belief unchanged. *It resolves:* whether the routing Wendell described works. *It unlocks:* shipping the
   feature.
2. **The map.** After the guided demo, the map shows the demo's channels in order with their moves, and a
   reader names the first channel, the move out of it and the last channel from the map alone. *It
   resolves:* whether the output is legible to a client. *It unlocks:* leading Cycle Complete with it.
